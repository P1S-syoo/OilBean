# 한강 오염 탐사 — 씬 배치 규칙 (Main3D)

> 배치/네이밍/사이즈 컨벤션을 합의로 누적 기록한다.
> Main3D 씬에 오브젝트를 배치할 때 모든 항목은 이 규칙을 따른다.
> (2.5D: 맵=3D, 캐릭터·UI=2D, 물리는 XY평면 Z=0)

## ① 네이밍 컨벤션 ✅ (확정 2026-06-06)

**그룹폴더 + 짧은이름 (계층 방식)**

- **부모 그룹** = 카테고리(복수형 권장): `Corals`, `Rocks`, `Hazards`, `Pickups`, `Kelp` …
- **자식** = `{Type}_{NN}` (2자리 인덱스, 1부터): `Coral_01`, `Rock_02`, `Hazard_01`
- 타입 구분은 **속한 부모 그룹**으로 한다(이름 짧게 유지).

```
Corals/
  ├ Coral_01
  ├ Coral_02
Rocks/
  ├ Rock_01
  ├ Rock_02
Hazards/
  ├ Hazard_01
```

## ② 오브젝트 타입 분류 ✅ (확정 2026-06-06)

**2.5D 깊이 레이어 기준**

| 레이어 | 역할 | 예시 |
|--------|------|------|
| `Background/` | 원경(카메라서 먼 배경) | 절벽, 먼 암초 |
| `Playfield/` | 플레이층(Z=0 상호작용 평면) | 잠수정, 산호, 바위, 해초 |
| `Foreground/` | 전경(카메라 앞 장식) | 가까운 해초·암초 실루엣 |
| `Gameplay/` | 게임 상호작용 객체 | 오염원, 수집물, 정화스팟 |
| `System/` | 비배치 시스템 | 카메라, 라이트, UI, Game |

> 각 레이어의 깊이(Z) 구체값은 ④에서 정의.

## ③ Hierarchy 그룹 구조 ✅ (확정 2026-06-06)

**레이어 > 타입그룹 > 오브젝트 (깊이 2단)**

```
Playfield/
  Corals/
    ├ Coral_01
    ├ Coral_02
  Rocks/
    ├ Rock_01
  Kelp/
    ├ Kelp_01
Gameplay/
  Hazards/
    ├ Hazard_01
  Pickups/
    ├ Pickup_01
```

- 최상위 = 깊이 레이어(②) → 타입 그룹(복수형) → `{Type}_{NN}` 오브젝트(①).

## ④ 타입별 배치 규칙 (Z깊이/평면/회전)

### ④-1 Z 깊이 ✅ (확정 2026-06-06)

**레이어별 Z 밴드(범위)** — 카메라는 -Z→+Z를 바라봄(작은 Z=가까움)

| 레이어 | Z 범위 |
|--------|--------|
| `Foreground` | -5 ~ -1 |
| `Playfield` | -0.3 ~ +0.3 |
| `Gameplay` | 0 (고정, 2D 물리 트리거) |
| `Background` | +3 ~ +15 |

> 범위 내에서 자유 배치해 자연스러운 깊이감을 준다. Gameplay만 Z=0 엄수.

### ④-2 회전/평면 ⏳ (논의 중)

## ⑤ 사이즈 컨벤션

### ⑤-1 규정 방식 ✅ (확정 2026-06-06)

**잠수정 상대 배수** — 잠수정 = 2×1 = **1.0배** 기준, 모든 타입을 배수 범위로 규정한다.

### ⑤-2 타입별 배수 🔶 (잠정 확정 2026-06-06 — 큰 오브젝트 실배치 후 세밀조정)

잠수정 = **1.0배(2×1)** 기준. **표준 톤** 채택.

| 타입 | 배수 범위 | 실길이(잠수정 2u 기준) |
|------|-----------|------------------------|
| Rock | 0.4 ~ 1.2 | 0.8 ~ 2.4u |
| Coral | 0.3 ~ 0.7 | 0.6 ~ 1.4u |
| Kelp | 0.8 ~ 1.5 | 세로 길쭉 |
| Cliff | 3 ~ 6 | 6 ~ 12u |
| Hazard | 0.5 ~ 1.0 | 1 ~ 2u |
| Pickup | 0.2 ~ 0.4 | 0.4 ~ 0.8u |
| Fish | 0.2 ~ 0.6 | 0.4 ~ 1.2u |

> 큰 오브젝트(절벽/지형)부터 배치해 스케일 감을 본 뒤 배수를 세밀조정한다.

### ⑤-3 지형/절벽 = 모듈러 블록 킷 ✅ (확정 2026-06-06)

지형·절벽·바위는 **에셋 대신 1u 그리드 모듈러 블록**으로 구성(데이브 더 다이버식). 유기물(산호/해초/생물)만 에셋·스프라이트.

- **블록 그리드 = 1×1×1u** (잠수정 = 가로2 세로1 블록)
- **4역할 킷**: `Wall`(벽 몸통) / `Top`(상단 마감) / `Corner`(모서리) / `Slope`(경사) — 조합해 절벽 벽 구성
- **블록감**: 각 블록 색 ±5% 변주 + 0.05u 틈(스케일 0.95)으로 격자감
- 머티리얼 `RockBlock`(URP Lit, 푸른 회색 0.42/0.50/0.55)
- 블록은 메시 원점이 항상 중심 → 오프셋 버그 없음
- 역할별 패턴 변형 개수는 추후 확장

#### per-face 텍스처 렌더링 ✅ (2026-06-08)
- 블록 = `4.Art/Models/VoxelBlock.asset`(2-서브메시: 윗면 / 옆·밑 5면) + per-face 머티리얼
- **윗면 = 오염 바닥**(노출된 곳만 보임), **옆면 = 가로 암반 지층**(전 블록 공유 → "지붕없는 블록" 자동 일치)
- UV: 옆면 세로(world Y)=텍스처 V로 통일 → 지층 가로 정렬 + 수직 seamless
- 텍스처 `4.Art/Textures/RiverbedTop(/1/2).png`(윗면 variant 3종), `RiverbedSide.png`(공유), 배경은 물색 틴트
- ChunkStreamer: 지형=variant별 [top,side], 배경(layer0)=흐림, 강변(layer3)=팔레트색
- 실제 AI 생성 텍스처로 PNG만 교체하면 즉시 반영(머티리얼 그대로)

#### 데이터화 (VARCO 연동) ✅
- 각 블록 = `BlockTile`(`IBlock` 구현, `role`+`variant` 보유) — `Assets/1.Scripts/World/`
- `BlockMap`이 자식 블록 전부 수집 → `Assets/6.Data/blockmap.json`(`{x,y,z,role,variant}`) export
- 역할×변형 머티리얼 12개(`4.Art/Materials/Blocks/`): **같은 (역할,변형)=동일 머티리얼 공유**(배칭 최적화), 다른 변형=다른 머티리얼
- 역할 자동 판정: 이웃 검사(위 비면 Top, 위+옆 비면 Corner, 그 외 Wall)
- **VARCO 워크플로**: blockmap.json → role/variant별 모델 생성 → JSON 좌표에 배치(교체)

### ⑤-4 절벽 Z 입체(3 Z레이어) ✅ (확정 2026-06-07)

절벽을 평면(Z0)이 아닌 **3개 Z레이어로 앞뒤 겹쳐** 입체화(데이브 더 다이버식). 카메라는 -Z→+Z.

| 레이어 | Z | 역할 | 처리 |
|--------|----|------|------|
| `Foreground` | -2 | 작은 앞 절벽(2×2 등) | 어둡게(실루엣), 충돌 없음 |
| `Playfield` | 0 | 통로 경계 메인 절벽 | 역할색 정상, 게임 충돌 |
| `Background` | +4 | 큰 배경 벽 | 수색 블렌드(멀수록 흐림), 큼 |

- 멀수록(+Z) 물색에 blend + 어둡게 → 대기원근으로 깊이감
- 메인(Playfield) 절벽 옆/앞에 작은 절벽 덩어리를 다른 Z에 산포

## ⑥ 맵 규모 + 렌더 스트리밍 ✅ (확정 2026-06-07)

대규모 맵을 청크 스트리밍 + 풀링으로 처리(보이는 범위+α만 렌더). 맵 크기 무관 메모리·렌더 상수.

- **맵 범위**(블록): X `-375~375`(가로 30화면), Y `-22~22`(세로 3화면) — `WorldGen.MinX..MaxX`
- **데이터 정의 = 절차 생성**: `WorldGen.Column(x,y)`가 좌표→블록 스펙(layer/role/variant). 10만 블록을 저장 않고 함수로 생성(VARCO export도 이 함수 샘플링)
- **청크**: 16×16 블록. 플레이어 주변 `radiusX/Y=2` → 5×5=25청크만 활성
- **풀링**: `BlockPool`이 큐브 GameObject 재사용(인스턴스/파괴 GC 회피)
- **스트리밍**: `ChunkStreamer`가 LateUpdate에서 플레이어 청크 변화 시 범위 밖 반납·범위 안 로드
- **검증**: 이동 전후 활성 블록 ≈5천 일정, 누수 0, 콘솔 에러 0 (전체 10만 중 5%만 렌더)
- 코드: `Assets/1.Scripts/World/` (WorldGen / BlockPool / Chunk(ChunkStreamer) / BlockTile / BlockMap)
- 머티리얼 팔레트 36개(`4.Art/Materials/Palette/`, layer×role×variant) — 동일 조합 공유(배칭)

#### 블록 충돌 ✅ (2026-06-07)
- **Playfield 노출 표면만** BoxCollider2D 활성(`WorldGen.Exposed`) — 320개 수준, 내부/배경/돌출은 끔
- ⚠️ 2D 콜라이더는 Z 무시 → **배경(+4)·돌출(-1)에 켜면 오충돌**. 반드시 Playfield(Z0)만.
- 잠수정: 본체 BoxCollider2D(2×1)=벽 충돌(비트리거) + CircleCollider2D(반경1.5)=수집 트리거 **분리**
  (이전 버그: Collector가 본체 콜라이더를 트리거로 만들어 벽 통과 → 센서 분리로 해결)
- 검증: 천장 향해 상승 시 y=5.01에서 정지(통과 안 함)

#### Foreground = 벽에 붙은 돌출 ✅ (2026-06-07)
- 떠있는 분리 슬랩(Z-2) → **Playfield 벽 노출 셀에 2×2 뭉치로 Z-1 돌출**(같은 XY를 카메라쪽 1칸)
- 벽 연장(role=Wall, 어둡게)로 처리 → 절벽에서 튀어나온 혹처럼 보임

## ⑦ 섹션 시스템 ✅ (확정 2026-06-07)

맵을 X축 **섹션(Section)** 단위로 나눠 성격을 바꾼다(레벨이 아니라 "섹션"). 섹션 폭 `SectionW=60`블록. `WorldGen.SectionAt(x)`가 결정적으로 타입 순환(통로→터널→개방).

| 타입 | 설명 | 구조 |
|------|------|------|
| `Corridor`(통로형) | 위아래 구불구불 통로 + 돌출 | 바닥(구불) + 천장(구불) + 가운데 통로 |
| `Tunnel`(터널형) | 다리 밑/구조물 아래 느낌 | 바닥 + **평평한 지붕**(y≥8) + **매달린 2×2 돌출**(8칸마다) |
| `Open`(일반형) | 위 트임, 바닥만 | 바닥만, 천장 없음(개방 수면) |

- 바닥은 전 구간 연속(구불) → 섹션 경계서 끊김 없이 이동
- 검증: 단면 ASCII로 3타입 확인(통로=양벽, 터널=`#####...###`+매달림, 개방=`...####`)
- 코드: `WorldGen.SectionType` / `SectionAt` / `IsSolid`의 섹션 분기

#### 섹션 시퀀스 고정 ✅ (2026-06-08)
- 순환이 아니라 **의도한 배열**로: `WorldGen.Sequence[]` (현재 테스트: `Open → Tunnel → Corridor`)
- 시작점 `OriginX=0`(플레이어 시작)이 시퀀스 [0]=일반. 맵 범위는 시퀀스 길이로 자동 결정
- 시퀀스 배열만 바꾸면 섹션 순서/길이 디자인 가능

#### 섹션 전환 블렌드 ✅ (2026-06-08)
- 경계에서 **천장 높이를 인접 섹션과 보간**(`CeilBot`, `BlendW=8`) → 갑작스런 벽 대신 비스듬한 오버행
- 개방=천장 "아주 높음"으로 취급 → 터널 진입 시 암반 천장이 점진 강하(검증: x58 y21→x68 y8)
- 바닥은 본래 연속이라 블렌드 불필요

#### 플레이어 회전 수정 ✅ (2026-06-07)
- 버그: 모델 좌향 flip에 **음수 스케일(scale.x=-1)** 사용 → Submarine 자식의 Y90 회전과 충돌해 회전/깊이 왜곡
- 수정: 음수 스케일 제거 → **Y180 뒤집기 + Z피치 보정**(`PlayerMove.ApplyModel`). 우향=Z피치, 좌향=Euler(0,180,180-heading). 상하 정상·왜곡 없음

## ⑧ 해수면 + 강변 백드롭 + 입자 ✅ (확정 2026-06-08)

### 해수면(WaterY=12)
- 모든 섹션 위 경계 = 해수면. 그 위로 못 올라감(`WaterCeiling` 와이드 BoxCollider2D, Kinematic, 플레이어 X 추적 `FollowX`)
- 일반형(Open)은 해수면까지 개방 → 수면 도달. 통로/터널은 암반 천장이 더 아래라 수면은 가려짐
- Playfield 천장 생성은 `y <= WaterY`로 제한(위는 공기)

### 강변 백드롭(3D 블록, 먼 Z+10) — `WorldGen` 레이어 3 "Shore"
- 구조(아래→위): 옹벽/강변(절벽, 탄색) → 인도(윗줄, 밝은회) → 빌딩(회색 기둥, 높이 변주, 사이는 하늘)
- `BuildingTop(x)`: 9칸 주기, 6칸 빌딩 + 3칸 간격(하늘), 높이 4~11 hash 변주
- 역할 매핑: 빌딩=Wall, 인도=Top, 옹벽=Slope → 팔레트 idx 36~47(Shore 머티리얼 12)
- 스트리밍으로 자동 로드(ChunkStreamer가 layer 0~3 전부 생성)

### 하늘
- `Sky` 퀀드(URP Unlit, 연파랑 0.55/0.78/0.96, 양면), Z+18, 밑면이 WaterY, 플레이어 X 추적
- 빌딩(Z+10)이 하늘(Z+18) 앞 → 빌딩 사이로 하늘. 수면 아래는 카메라 teal 배경(물)

### 입자(플랑크톤/기포)
- `Bubbles` 프리팹(ParticleSystem) 복원, Main Camera 자식, `simulationSpace=World`(드리프트), 144개 — 오염된 수중 느낌

## ⑨ 기타 (좌표 기준·정렬 등) ⏳
